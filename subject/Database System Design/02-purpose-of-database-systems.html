DATABASE SYSTEM DESIGN   /   UNIT 01

Purpose of Database Systems

Database system sirf data rakhne ki jagah nahi—ye data ko efficiently aur reliably store, retrieve, modify aur protect karne ka tareeka hai.

Topic 02 Unit 01 / Database systems Prepared 27 Sep 2026

START HERE / FROM FILES TO A SYSTEM

Hume database system ki zarurat kyun hai?

Socho ek college student, faculty, attendance, fees aur marks ke liye alag-alag files rakhta hai. Har file apne kaam ke liye useful hai, lekin Rohan ka naam, roll number ya phone number kai files mein repeat ho sakta hai. Organization badi hone par aise scattered records ko dhoondhna, update karna aur sahi rakhna mushkil hota hai.

Database system ka main purpose hai data ko efficiently aur reliably manage karna. Pehle note mein DBMS ki definition aur introductory need padhi thi; yahan focus un specific purposes par hai jo exam mein list aur explain karne hote hain.

Traditional file system ki problem

Student.txt      Rohan | CSE | 101 | 9876543210
Fees.txt         Rohan | 101 | ₹80,000
Attendance.txt   Rohan | 101 | 85%
Marks.txt        Rohan | 101 | 85

Ek hi vyakti ki details kai jagah faili hui hain. Aage ke points dikhate hain ki database system is data ko kaise useful, controlled aur dependable banata hai.

01 / KEEP LARGE DATA ORGANIZED

Data storage

Database system large amount of data ko systematically store karne mein madad karta hai. College example mein ek saath students, courses aur attendance ke bahut saare records manage karne hote hain.

College database
  ├── 10,000 students
  ├── 50,000 courses
  └── 1,00,000 attendance records

Records organized hon, toh baaki kaam—jaise kisi ek student ka record dhoondhna ya update karna—zyada seedha ho jata hai.

02 / FIND THE REQUIRED RECORD

Easy data retrieval

User ko aksar poora database nahi, sirf ek particular answer chahiye. Jaise: Rohan ke marks dikhao. Database system request ke mutabik relevant record retrieve karta hai.

User request: “Rohan ke marks dikhao.”
        ↓
Database system searches records
        ↓
Required result: Marks = 85

03 / CHANGE THE RECORDS

Data modification

Stored data ko zarurat par insert, update ya delete kiya ja sakta hai. Agar Rohan ka phone number badal jaye, toh nayi value record mein update ki ja sakti hai.

Old phone  →  9876543210
New phone  →  8765432109

Yahan main idea data ko badalne ki capability hai; abhi kisi particular database command ya syntax ki baat nahi ho rahi.

04 / AVOID NEEDLESS COPIES

Reduce data redundancy

Redundancy ka matlab same data ka unnecessary repetition hai. Agar student ki common details attendance, fees, marks aur library files mein baar-baar likhi hon, toh extra copies maintain karni padti hain. Database system redundancy ko reduce karne mein madad karta hai.

Redundancy ka basic example Introduction to DBMS note mein bhi dekha tha; yahan ise database systems ke purpose ke roop mein yaad rakho.

05 / KEEP RELATED VALUES IN AGREEMENT

Maintain data consistency

Consistency ka matlab hai data alag jagah par logically same rahe. Agar phone number ek file mein 9999999999 ho aur doosri mein purana 8888888888, toh records inconsistent hain.

Centralized aur controlled data management conflicting copies ko kam karke consistency maintain karne mein help karta hai.

06 / GIVE THE RIGHT ACCESS

Data security

Har user ko poore database ka access dena safe nahi hota. Database system authorization aur access control ke zariye define karne mein madad karta hai ki kaun-sa user kya dekh ya change kar sakta hai.

  • Student: apne marks dekh sakta hai.
  • Faculty: students ke marks dekh ya update kar sakti hai.
  • Admin: poore system ko manage kar sakta hai.
CLARITY NOTE / PREREQUISITE

Authorization batata hai user ko kis action ki permission hai; access control un permissions ke mutabik access ko limit karta hai.

07 / KEEP VALUES VALID

Data integrity

Data valid aur accurate hona chahiye. Database constraints invalid values ko rokne mein help karte hain.

Age = 20     valid
Age = 25     valid
Age = -10    invalid

08 / MORE THAN ONE USER

Concurrent access

Concurrent access ka matlab multiple users ka same database ko simultaneously access kar pana hai. Student, faculty, admin aur accountant apne kaam ke liye system use kar sakte hain.

DBMS simultaneous operations ko coordinate karta hai, taaki ek hi waqt par kiye gaye changes database ko inconsistent na bana dein. Is idea ko baad mein Transaction Management and Concurrency Control ke andar detail mein padhenge.

09 / PREPARE FOR FAILURE

Backup and recovery

System crash ya hardware failure ke baad important data restore kar pana zaroori hai. Database system backup aur recovery mechanisms ke zariye lost data ko recover karne mein madad karta hai.

Database → Backup → System failure
                         ↓
                  Recovery → Data restored

PUT THE PURPOSES TOGETHER

College ka end-to-end example

10,000 students wale college mein scattered files duplicate records, conflicting values, difficult searching aur security problems la sakti hain. DBMS users aur organized college data ke beech controlled access deta hai, aur storage, retrieval, modification, consistency, integrity aur recovery ke kaam support karta hai.
