DATABASE SYSTEM DESIGN   /   UNIT 01

View of Data

Database andar se complex ho sakta hai; database system user ko uske kaam ke mutabik ek simple view dikhata hai.

Topic 04 Unit 01 / Database systems Prepared 27 Sep 2026

START HERE / ONE DATABASE, DIFFERENT NEEDS

Har user ko sab kuch dikhana zaroori nahi

College database ke andar Student, Faculty, Course, Department, Attendance, Marks, Fees, Examination aur Library jaise records ho sakte hain. Database ka actual storage aur implementation user ke liye complex hota hai. Student ko shayad apna naam, roll number, courses, attendance aur marks hi chahiye—not storage ke internal details.

Isliye database system data ko alag levels of abstraction par present karta hai. Har level ek alag sawaal ka jawab deta hai: data kaise store hai, database mein kya hai, aur is user ko kya dikhana hai?

THE CORE IDEA

Data abstraction kya hai?

EXAM DEFINITION

Data abstraction complex database details ko hide karke user ko sirf required information dikhane ka process hai.

ATM use karte waqt screen par Balance, Withdraw, Deposit aur Transfer jaise options dikhte hain. User ko bank ke internal server, DBMS, database ya transaction processing ki details nahi dikhni padti. System un details ko background mein handle karta hai.

01 / LOWEST LEVEL

Physical Level

Physical level abstraction ka lowest level hai. Ye batata hai ki data computer storage mein kaise physically stored hai.

  • Files aur disk blocks
  • Storage pages aur structures
  • Indexes
  • Memory locations

Student table ke physical level par concern ye hoga ki uska data disk blocks, storage pages ya index structures mein kaise rakha gaya hai. Normal user ko in details ki zarurat nahi hoti.

EXAM DEFINITION

Physical level describes how data is physically stored in the database.

02 / MIDDLE LEVEL

Conceptual Level

Conceptual level batata hai database mein kaunsa data hai aur us data ke beech relationships kya hain. Ye poore database ki overall logical structure describe karta hai.

STUDENT                 COURSE

STUDENT ───── enrolls in ───── COURSE

Is level par Student aur Course ke data aur unka relation samajh aata hai; physical storage details hide rehti hain.

EXAM DEFINITION

Conceptual level describes the overall logical structure of the database.

03 / HIGHEST LEVEL

View Level

View level abstraction ka highest level hai. Ye define karta hai ki particular user ko database ka kaunsa portion dikhana hai.

Same college database / role ke mutabik alag view
UserUska view
StudentName, Roll No., Courses, Attendance, Marks
FacultyStudent Name, Roll No., Attendance, Marks
AccountantStudent Name, Roll No., Fees, Payment Status

Database same hai, lekin user aur uske kaam ke hisaab se dikhne wali information alag ho sakti hai.

EXAM DEFINITION

View level describes the portion of the database visible to an individual user.

PUT THE LEVELS TOGETHER

Three-level architecture

Users apne views dekhte hain. Ye views conceptual level ke overall logical database par based hote hain, jo physical level ke storage details se supported hota hai.

Order yaad rakho: View → Conceptual → Physical → Storage.

WHY ABSTRACTION HELPS

Ye levels useful kyun hain?

Abstraction se user ko internal complexity samajhne ki zarurat nahi padti. Google Drive mein file kholte waqt user ko ye nahi sochna padta ki file SSD ke kis block mein stored hai—user ko file ka apna view milta hai; system storage details handle karta hai.

ANALOGY / REMEMBER THE IDEA

Restaurant example

Customer menu aur food dekhta hai; kitchen aur storage ke internal process usse hidden rehte hain. Ye example abstraction ka broad idea samjhata hai—kuch details user ko dikhana aur baaki hide karna.

CLARITY NOTE / ANALOGY LIMIT

Restaurant ke customer, manager aur kitchen ko database ke teen levels ke exact equivalents mat samjho. Conceptual level manager ka personal view nahi; ye poore database ki logical structure hai.
