THEORY · Q1

Client/Server model kya hai?

QUESTION

What is a Client/Server Model?

ANSWER

Client/Server model network ka wo design hai jisme kaam maangne wala (client) aur dene wala (server) alag-alag hote hain. Client request bhejta hai, server usko process karke response deta hai. Formula: Request → Process → Response.

OVERLAP FLAG / QB CLARITY

Q1 aur Q6 dono client/server par hain. Exam strategy: Q1 mein short definition + roles + example likho; poora diagram + working steps + fayde/nuksaan Q6 mein likho. Dono mein same diagram repeat mat karo.

EXAM DEFINITION

The client/server model is a network architecture in which clients request services and servers provide them — e.g. a web browser (client) fetching pages from a web server.

Roles ek line mein: Client — service maangta hai (browser, mobile app, ATM machine); khud data store nahi karta (MCQ 1: client requests services). Server — service deta hai (web/database/mail server), 24×7 chalta hai (MCQ 2, detail Q2 mein).

Roz ke 3 examples pakke karo: browser → website kholna; ATM → bank server se balance nikaalna; email app → mail server se mail laana. Har example mein maangne wala client, dene wala server — yehi line examiner dhoondhta hai.

Exam-ready plan: definition + Request→Process→Response formula, client vs server 2-line roles (MCQ 1–2 link), 2–3 examples, “detail + diagram Q6 mein” wali line. Chhota answer hai — 1 page se zyada mat kheecho.

Analogy: Restaurant mein tum (client) order dete ho, waiter request kitchen (server) tak pahunchata hai, khana bankar wapas aata hai — tum khana banate nahi, sirf maangte ho.

THEORY · Q2

Server kya hai?

QUESTION

What is a server?

ANSWER

Server wo powerful computer ya program hai jo network par clients ko services deta hai — files, websites, emails, ya data. Client maangta hai, server deta hai (MCQ 2 ka answer: server provides services).

EXAM DEFINITION

A server is a computer or program that provides services, data, or resources to client devices over a network, typically running continuously (24×7).

Server ki 5 pehchan (characteristics):

  • Always-on (24×7): raat ko 3 baje bhi website khulti hai — server kabhi sota nahi.
  • Powerful hardware: tez processor, badi memory/storage — hazaaron clients ek saath sambhalta hai.
  • Central storage + backup: data ek jagah, backup ke saath — client mein data khone ka darr nahi.
  • Security: login/password, firewall — galat haath data tak nahi pahunchte.
  • Fixed address: clients ko pata ho ki server kahan milega (IP address — Q3 se jodo).

Types + example (table yaad karo): Web server (websites — MCQ 3 mein browser client hai, ye server hai), database server (data store), mail server (emails), file server (office files), DNS server (naam se address — Q7 mein aayega).

Exam-ready plan: definition, 4–5 characteristics har ek ek-line matlab, types ki list with example, MCQ 2–3 link line.

THEORY · Q3

IP address kya hai?

QUESTION

What is an IP address?

ANSWER

IP address (Internet Protocol address) network par har device ka unique logical pata hai — jaise har ghar ka postal address. Isi pate par packets bheje jaate hain (MCQ 4: internet communication ka protocol = IP; MCQ 5: IP = Internet Protocol).

OVERLAP FLAG / QB CLARITY

Q3 aur Q8 dono IP par hain. Exam strategy: Q3 mein short definition + format + example likho; classes, versions aur transmission types ka detail Q8 mein likho.

EXAM DEFINITION

An IP address is a unique logical identifier assigned to each device on a network, used to route data to the correct destination — e.g. 192.168.1.1 (IPv4).

Format (IPv4): 32-bit number, 4 hisson (octets) mein, dots se likha — 192.168.1.1. Har hissa 0–255. IPv6 naya version hai (128-bit, zyada addresses — detail Q8 mein).

2 khaas baatein: Unique hota hai — ek network mein do devices ka same IP nahi (takraav hoga). Logical/changeable hota hai — MAC ki tarah chip mein fixed nahi; network badlo toh IP badal sakta hai (yehi Q4 ka farq hai).

Exam-ready plan: definition + IP full form (MCQ 5), IPv4 format + example, unique + logical 2 lines, “detail Q8 mein” line.

THEORY · Q4

IP address vs MAC address

QUESTION

What is the difference between IP address and MAC address?

ANSWER

Dono device ke “pate” hain par level alag: IP = logical pata (badal sakta hai, poori duniya mein routing ke liye), MAC = physical pata (chip mein fixed, sirf local network mein kaam). Yaad rakhne ki line: IP ghar ka postal address hai (shift ho toh badalta hai), MAC aadhaar number hai (janam se fixed).

THEORY · Q6

Client/Server model — diagram ke saath detail

QUESTION

Explain the Client/Server model with a suitable diagram.

ANSWER

Q1 mein short definition thi — yahan poora working + diagram + fayde/nuksaan likho. Model ke 3 hisse: client (request), network (rasta), server (service + data).

Working — 4 steps (numbering mein likho): 1) Client request banata hai (jaise browser mein www.example.com khola). 2) Request network (internet) se server tak jaati hai. 3) Server request process karta hai — data nikaalta, check karta hai. 4) Response wapas client ko — page screen par dikhta hai.

Fayde (3): centralized data (backup easy), security (ek darwaza), maintenance (server update = sab updated). Nuksaan (2): server down = sab down (single point of failure), powerful server costly hai.

Exam-ready plan: 3 hisse line, 4 numbered working steps, FIG.001, 3 fayde + 2 nuksaan, 2 examples. Diagram mein request/response arrows label karna mat bhoolna.

THEORY · Q7

Internet communication — detail mein

QUESTION

Explain Internet communication in detail.

ANSWER

Internet communication matlab data ka sender se receiver tak chhote packets mein tootkar, sahi raste se, sahi kram mein pahunchna. Poora safar 5 steps mein:

  • Step 1 — Address lagao (IP + DNS): har device ka IP pata (Q3); naam (www.example.com) ko DNS server IP mein badalta hai — phonebook jaisa.
  • Step 2 — Todo (packets): bada data chhote packets mein tootta hai; har packet par sender/receiver IP + number lagta hai.
  • Step 3 — Bhejo (routing): routers har packet ka best rasta chunte hain; alag packets alag raste se bhi ja sakte hain (packet switching).
  • Step 4 — Bharosa (TCP): receiver TCP se check karta hai — khoya packet dobara mangwata hai, kram lagata hai (Q5 se jodo).
  • Step 5 — Jodo (reassembly): packets judkar original photo/video/page banta hai.

Kaun kya karta hai (exam table jaisi list): IP — pata + routing (MCQ 4); TCP/UDP — bharosa ya speed; DNS — naam se number; Router — rasta; ISP — internet ka gate.

Exam-ready plan: packets wali opening line, 5 numbered steps, FIG.004, 5 roles ek-line mein. DNS wali line zaroor likho — examiner ko pasand hai.

Analogy: Courier mein sofa kholkar dabbon mein bhejo (packets), har dabbe par pata (IP), alag trucks alag raste (routers), ghar par kholo-jodo, toota samaan wapas mangwao (TCP).

THEORY · Q9

MAC address aur uski importance

QUESTION

Explain MAC addresses and their importance.

ANSWER

MAC (Media Access Control) address har network card (NIC) ka factory mein fixed physical pata hai — 48-bit, hex mein colons se likha, jaise 3C:22:FB:11:AA:09. Pehle 3 hisse company (OUI — kisne banaya), aakhri 3 device ka unique number.

EXAM DEFINITION

A MAC address is a permanent 48-bit physical identifier burned into a network interface card, used for device delivery inside a local network.

Importance — 4 points (exam mein yahi maanga hai):

  • Local delivery: switch MAC dekhkar packet sahi computer tak pahunchata hai — IP duniya ka rasta dikhata hai, MAC mohalle ka ghar (Q4 se jodo).
  • ARP ka saathi: ARP (Address Resolution Protocol) IP se MAC nikaalta hai — bina MAC ke local delivery impossible.
  • Security (MAC filtering): router/Wi-Fi mein allowed MACs ki list — anjaan device jud hi nahi sakta (hostel Wi-Fi jaisa).
  • Uniqueness + tracking: duniya mein do same MAC nahi — device pehchan aur troubleshooting mein kaam aata hai.

Exam-ready plan: definition + format + OUI line, 4 importance points har ek ek-line matlab, ARP ek line, Q4 table se link. Format ka example haath se likhkar dikhao.

THEORY · Q10

Networking ka IoT mein role

QUESTION

Explain the role of networking in IoT.

ANSWER

Bina networking ke IoT sirf akele gadgets hain — networking hi unko system banati hai. Sensor kheton mein, server cloud mein, mobile tumhari jeb mein — jodne wala dhaaga network hai.

4 roles (headings mein likho):

  • Data transport: sensor ka data gateway/cloud tak — paas ke liye Wi-Fi/Bluetooth/Zigbee, door ke liye LoRa/cellular (har range ka option).
  • Remote monitoring + control: ghar baithe motor on/off, hospital mein patient stats — monitoring aana, command jaana, dono network se.
  • Scalability: 10 devices se 10,000 tak — IP addressing + routers se network badhta hai (Q8 se jodo).
  • Interoperability: alag companies ke devices standard protocols (IP, MQTT, CoAP) se aapas mein baat karte hain.

2 examples pakke karo: smart home (sensor → Wi-Fi → phone app → AC on) aur health band (sensor → Bluetooth → phone → doctor). Dono mein data ka rasta likho — wahi networking ka role hai.

Exam-ready plan: akeele-gadget wali opening line, 4 roles har ek example ke saath, 2 full examples data-raste ke saath, Q11 ka hint (agriculture mein bhi yahi roles).

Analogy: Gadgets sharir ke ang hain, network nervous system hai — dimaag (cloud) tak signal pahunchana aur hukum wapas laana uska kaam hai.

THEORY · Q12

Domain, Information aur Service — IoT mein

QUESTION

Explain Domain, Information and Service in IoT.

ANSWER

Ye teeno IoT system ko samajhne ke 3 lens hain — kahan (domain), kya data (information), kya kaam (service):

  • Domain: system ki duniya — physical entity (asli cheez: khet, patient, gaadi) + virtual entity (uski cloud copy: digital record). Domain batata hai hum kis duniya ka system bana rahe hain (agriculture domain, health domain).
  • Information: entities ke baare mein data — attributes (nami = 30%, temp = 35°C) aur unki values. Information model decide karta hai kaunsa data collect hoga, kaise store hoga.
  • Service: entity par koi kaam karne wala function — sensing service (temperature padho) aur actuation service (pump chalao). App service ko bulati hai, service hardware se baat karti hai (MCQ 7–8: operation = component ki detailed activity; integration = components ko jodkar chalana).

What is a Client/Server model?

QUESTION

What is a Client/Server Model?

ANSWER

The client/server model is the network design where the asker (client) and the giver (server) are separate. The client sends a request, the server processes it and returns a response. Formula: Request → Process → Response.

OVERLAP FLAG

Q1 and Q6 are both on client/server. Exam strategy: write a short definition + roles + examples in Q1; full diagram + working steps + pros/cons go in Q6. Do not repeat the same diagram in both.

EXAM DEFINITION

The client/server model is a network architecture in which clients request services and servers provide them — e.g. a web browser (client) fetching pages from a web server.

Roles in one line each: Client — asks for service (browser, mobile app, ATM machine); stores no data itself (MCQ 1: client requests services). Server — gives service (web/database/mail server), runs 24×7 (MCQ 2, detailed in Q2).

Fix 3 everyday examples: browser → opening a website; ATM → withdrawing balance from the bank server; email app → fetching mail from the mail server. In each, the asker is the client and the giver is the server — this is exactly the line the examiner looks for.

Exam-ready plan: definition + Request→Process→Response formula, 2-line client vs server roles (MCQ 1–2 link), 2–3 examples, “details + diagram in Q6” line. It is a short answer — do not stretch beyond a page.

THEORY · Q2

What is a server?

QUESTION

What is a server?

ANSWER

A server is the powerful computer or program that gives services to clients on a network — files, websites, emails, or data. Clients ask, servers give (MCQ 2's answer: server provides services).

EXAM DEFINITION

A server is a computer or program that provides services, data, or resources to client devices over a network, typically running continuously (24×7).

5 hallmarks of a server (characteristics):

  • Always-on (24×7): websites open even at 3 AM — servers never sleep.
  • Powerful hardware: fast processor, big memory/storage — handles thousands of clients together.
  • Central storage + backup: data in one place, with backup — no fear of losing data on clients.
  • Security: logins/passwords, firewalls — wrong hands never reach the data.
  • Fixed address: clients know where to find it (IP address — link to Q3).

Types + example (memorize the table): web server (websites — in MCQ 3 the browser is the client, this is the server), database server (data storage), mail server (emails), file server (office files), DNS server (names to addresses — coming in Q7).

Exam-ready plan: definition, 4–5 characteristics each with a one-line meaning, types list with examples, MCQ 2–3 link line.

THEORY · Q3

What is an IP address?

QUESTION

What is an IP address?

ANSWER

An IP address (Internet Protocol address) is every device's unique logical address on a network — like every home's postal address. Packets are sent to this address (MCQ 4: the protocol for internet communication = IP; MCQ 5: IP = Internet Protocol).

OVERLAP FLAG

Q3 and Q8 are both on IP. Exam strategy: write a short definition + format + example in Q3; classes, versions, and transmission types go in detail in Q8.

EXAM DEFINITION

An IP address is a unique logical identifier assigned to each device on a network, used to route data to the correct destination — e.g. 192.168.1.1 (IPv4).

Format (IPv4): a 32-bit number in 4 parts (octets), written with dots — 192.168.1.1. Each part is 0–255. IPv6 is the newer version (128-bit, more addresses — detail in Q8).

2 special facts: it is unique — two devices in one network never share an IP (collision). It is logical/changeable — not fixed in a chip like MAC; change networks and the IP can change (exactly Q4's difference).

Exam-ready plan: definition + IP full form (MCQ 5), IPv4 format + example, unique + logical two lines, “detail in Q8” line.

THEORY · Q4

IP address vs MAC address

QUESTION

What is the difference between IP address and MAC address?

ANSWER

Both are a device's “addresses” but at different levels: IP = logical address (changeable, for routing across the world), MAC = physical address (fixed in the chip, works only in the local network). Memory line: IP is the home's postal address (changes on shifting), MAC is the national ID number (fixed from birth).

THEORY · Q6

Client/Server model — in detail with diagram

QUESTION

Explain the Client/Server model with a suitable diagram.

ANSWER

Q1 had the short definition — here write full working + diagram + pros/cons. The model has 3 parts: client (request), network (path), server (service + data).

Working — 4 steps (write numbered): 1) The client builds a request (e.g. opening www.example.com in a browser). 2) The request travels over the network (internet) to the server. 3) The server processes the request — fetches data, checks it. 4) The response returns to the client — the page appears on screen.

Advantages (3): centralized data (easy backup), security (one door), maintenance (update the server = everyone updated). Disadvantages (2): server down = all down (single point of failure), powerful servers are costly.

Exam-ready plan: 3-parts line, 4 numbered working steps, FIG.001, 3 pros + 2 cons, 2 examples. Never forget to label the request/response arrows in the diagram.

THEORY · Q7

Internet communication — in detail

QUESTION

Explain Internet communication in detail.

ANSWER

Internet communication means data broken into small packets, travelling correct routes, and arriving in correct order from sender to receiver. The whole journey in 5 steps:

  • Step 1 — Address it (IP + DNS): every device has an IP address (Q3); names (www.example.com) are converted to IPs by the DNS server — like a phonebook.
  • Step 2 — Break it (packets): big data splits into small packets; each packet gets sender/receiver IPs + a number.
  • Step 3 — Send it (routing): routers pick each packet's best path; different packets may even take different routes (packet switching).
  • Step 4 — Trust it (TCP): the receiver checks via TCP — re-demands lost packets, sets the order (link to Q5).
  • Step 5 — Join it (reassembly): packets join into the original photo/video/page.

Who does what (exam-style list): IP — address + routing (MCQ 4); TCP/UDP — trust or speed; DNS — numbers from names; router — path; ISP — the internet's gate.

Exam-ready plan: packets opening line, 5 numbered steps, FIG.004, 5 roles one line each. Always write the DNS line — examiners love it.

THEORY · Q9

MAC addresses and their importance

QUESTION

Explain MAC addresses and their importance.

ANSWER

A MAC (Media Access Control) address is every network card's (NIC) factory-fixed physical address — 48-bit, written in hex with colons, e.g. 3C:22:FB:11:AA:09. The first 3 parts name the maker (OUI — who built it), the last 3 the device's unique number.

EXAM DEFINITION

A MAC address is a permanent 48-bit physical identifier burned into a network interface card, used for device delivery inside a local network.

Importance — 4 points (exactly what the exam asks):

  • Local delivery: the switch reads the MAC to reach the right computer — IP shows the world's route, MAC the neighbourhood home (link to Q4).
  • ARP's partner: ARP (Address Resolution Protocol) derives MAC from IP — local delivery is impossible without MAC.
  • Security (MAC filtering): routers/Wi-Fi keep a list of allowed MACs — unknown devices simply cannot join (like hostel Wi-Fi).
  • Uniqueness + tracking: no two MACs in the world match — useful for device identity and troubleshooting.

Exam-ready plan: definition + format + OUI line, 4 importance points each with a one-line meaning, ARP one line, link to the Q4 table. Write the format example out by hand.

THEORY · Q10

Role of networking in IoT

QUESTION

Explain the role of networking in IoT.

ANSWER

Without networking, IoT devices are just lonely gadgets — networking turns them into a system. Sensors in fields, servers in the cloud, mobiles in your pocket — the network is the thread joining them.

4 roles (write under headings):

  • Data transport: sensor data to gateway/cloud — Wi-Fi/Bluetooth/Zigbee nearby, LoRa/cellular far away (an option for every range).
  • Remote monitoring + control: switch motors on/off from home, patient stats in hospitals — monitoring comes in, commands go out, both via network.
  • Scalability: from 10 devices to 10,000 — IP addressing + routers grow the network (link to Q8).
  • Interoperability: devices from different companies talk via standard protocols (IP, MQTT, CoAP).

Fix 2 examples: smart home (sensor → Wi-Fi → phone app → AC on) and health band (sensor → Bluetooth → phone → doctor). Write the data path in both — that path is networking's role.

THEORY · Q12

Domain, Information and Service in IoT

QUESTION

Explain Domain, Information and Service in IoT.

ANSWER

These three are 3 lenses for understanding an IoT system — where (domain), what data (information), what job (service):

  • Domain: the system's world — physical entity (the real thing: field, patient, car) + virtual entity (its cloud copy: digital record). The domain tells which world's system we are building (agriculture domain, health domain).
  • Information: data about entities — attributes (moisture = 30%, temp = 35°C) and their values. The information model decides which data is collected and how it is stored.
  • Service: a function doing some job on an entity — sensing service (read temperature) and actuation service (run the pump). The app calls the service, the service talks to hardware (MCQ 7–8: operation = a component's detailed activity; integration = making components work together).

  1. Q1. In the Client/Server model, the client primarily?

    Answer: A — the browser asks; the other three give (they are servers).

    A) IP · B) HTML · C) USB · D) HDMI
    Answer: A — IP addresses + routes; HTML builds pages, USB/HDMI are cable standards (Q7).

    A) Internet Process · B) Internet Protocol · C) Internal Protocol · D) Information Processing
    Answer: B — Internet Protocol; recognize it by the word “Protocol” (Q3).

  6. Q6. Which of the following is an example of an IoT function?

    A) Reading a sensor · B) Choosing a font · C) Opening a text editor · D) Formatting a document
    Answer: A — reading a sensor is a sensing service; the rest are ordinary computer jobs (Q12).

  7. Q7. An operation in IoT represents?

    A) A detailed activity performed by a component · B) A domain name · C) An IP address · D) A user password only
    Answer: A — an operation = a component's concrete job, e.g. readMoisture() (Q12).

  8. Q8. Component integration means?

    Answer: A — joining sensor + board + cloud to run; Q11's step-9 (Q11).

  9. Q9. Which of the following can be an IoT component?

    A) Sensor · B) Actuator · C) Microcontroller · D) All of the above
    Answer: D — senser + mover + brain — all three are needed (Q11/Q12).

  10. Q10. Which component converts a physical parameter into a measurable signal?

    A) Sensor · B) Actuator · C) Router · D) Server
    Answer: A — the sensor takes input (heat→signal); the actuator is the reverse — signal→motion (Q12).
